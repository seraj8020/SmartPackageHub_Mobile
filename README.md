# SmartPackageHub_Mobile

React Native (Expo) app for **Resident** and **Staff**, sitting next to `SmartPackageHub_UI` / `SmartPackageHub_API`.

Admin Portal stays in the web UI for now.

## Stack

- Expo SDK 58 + React Native
- TypeScript
- React Navigation (native stack + bottom tabs)
- `expo-camera` (barcode; Google ML Kit / platform scanners)
- `@react-native-ml-kit/text-recognition` (on-device OCR)
- `expo-sqlite` + `@react-native-community/netinfo` (offline intake queue)
- `expo-dev-client` (development builds for native modules)

**Does not work in Expo Go:** on-device OCR (`@react-native-ml-kit/text-recognition`) and other custom native modules — use a **development build** (emulator or device) for Staff Scan OCR.

### Android Studio emulator / development build

| Tool | Notes |
|------|--------|
| **Android Studio** | Latest stable |
| **Android SDK** | Platform tools + an emulator system image (x86_64 / arm64) |
| **Android Emulator** | e.g. Medium Phone API 35+ |
| **JDK 17** | Required for Gradle / `expo run:android` |

Create and start a Virtual Device from **Android Studio → Device Manager** before running the app.

#### Windows tips (native build)

- Prefer a **short project path** (this repo uses `D:\Sph\...`).
- If CMake/Ninja fails with *Filename longer than 260 characters*, enable Windows long paths (Admin PowerShell), reboot, and/or install a newer Android SDK **CMake 3.31+** (includes Ninja 1.12+). See [Expo: Windows long paths](https://docs.expo.dev/troubleshooting/windows-long-paths/).
- `/android` is generated by prebuild and is gitignored — regenerate with `npx expo prebuild` when needed.

## How to run

### A) Expo Go on a physical phone

Fast JS iteration (no OCR / ML Kit). **Must use Expo Go mode** — not the `exp+smartpackagehubmobile://` development-build link.

```bash
cd SmartPackageHub_Mobile
npm install
npm run start:go
# same as: npx expo start --go
```

Then:

1. Open **Expo Go** on the phone (same Wi‑Fi as the PC).
2. Scan the QR code — it should look like `exp://192.168.x.x:8081` (not `exp+smartpackagehubmobile://`).
3. If the LAN QR fails, press `s` in the terminal for **tunnel**, or run:

```bash
npx expo start --go --tunnel
```

If Metro was already started by `expo run:android`, stop it (`Ctrl+C`) and start again with `npm run start:go`.

**API URL on a real phone:** do not use `localhost` in `.env`. Use the QA host or your PC LAN IP, e.g. `EXPO_PUBLIC_API_BASE_URL=http://192.168.1.4:5210` or the default QA `http://34.180.50.189:5000`.

### B) Android Studio emulator

**Option 1 — Expo Go on the emulator** (same as phone, no OCR):

1. Install **Expo Go** from Play Store on the emulator (or sideload).
2. Run `npm run start:go`, then press `a` to open on Android.

**Option 2 — Development build** (full native / OCR):

```bash
cd SmartPackageHub_Mobile
npm install

# Start the emulator first (Android Studio Device Manager), or let Expo launch it

npx expo prebuild --platform android
npm run android
# same as: npx expo run:android
```

After install:

1. Emulator opens **Smart Package Hub Development Build** (Dev Launcher).
2. Allow permission prompts if shown.
3. If it does not auto-connect, use `http://localhost:8081` and tap **Connect**.
4. For later JS-only reloads (APK already installed):

```bash
npm run start:dev
# same as: npx expo start --dev-client
```

| Goal | Command | URL / app |
|------|---------|-----------|
| Phone + Expo Go | `npm run start:go` | Scan `exp://…` in Expo Go |
| Emulator + Expo Go | `npm run start:go` then `a` | Expo Go |
| Emulator + OCR / ML Kit | `npm run android` or `npm run start:dev` | Dev client (`exp+smartpackagehubmobile://`) |

You normally pick **one** Metro mode at a time (`--go` **or** `--dev-client`). Reset cache with `npx expo start -c` if the bundle looks stale.

### C) iOS Simulator (macOS only)

```bash
npx expo prebuild --platform ios
npx expo run:ios
```

## Why expo-camera (not Vision Camera)

For this Expo managed app, `expo-camera` is the better free default:

- Barcode path uses Google’s scanner stack on Android and Apple Vision/DataScanner on iOS
- Official Expo config plugin + simpler CNG / EAS setup
- Fast enough for AWB / tracking labels; OCR runs on a captured frame after barcode lock (same UX as web)

`react-native-vision-camera` + ML Kit frame processors can be slightly faster for continuous OCR, but costs more native complexity. Stay on Expo modules unless you need continuous frame OCR later — still free via Google ML Kit either way.

## Staff Scan (wired)

Mirrors web Package Intake:

1. Live barcode scan → lock AWB
2. Capture frame → on-device OCR → fill courier / name / tower / flat
3. Resident match / search via `/api/v2/intake/match` and `/intake/residents`
4. Confirm via `POST /api/v2/intake/confirm`
5. Offline flush via `POST /api/v2/intake/batch-intake`

### Offline intake queue

Basement / garage dead zones are expected. Confirm always succeeds locally:

- Payload stored in SQLite (`intake_queue`)
- Flushed to `POST /api/v2/intake/batch-intake` when online (falls back to single confirm)
- Exponential backoff (2s → 15m) + NetInfo reconnect + 30s sweep
- Same `clientRequestId` keeps retries idempotent on the server

## API

Default host: `http://34.180.50.189:5000` (`EXPO_PUBLIC_API_BASE_URL`). Paths use `/api/v2`.

## Auth

- Resident OTP + Staff login
- Tokens/sessions in Expo SecureStore

## Staff Inbox / Shelf (wired)

- **Inbox** — Received packages → assign shelf (`GET /societies/{id}/packages`, shelf inventory, `POST /packages/{id}/shelf`)
- **Shelf** — Shelved packages → dispatch (`PUT /packages/{id}/dispatch`)
- COD packages stay blocked until resident approval

## Resident Inbox (wired)

- Shelved packages list + COD approve/reject dialog
- Door-slot booking navigation not included yet
